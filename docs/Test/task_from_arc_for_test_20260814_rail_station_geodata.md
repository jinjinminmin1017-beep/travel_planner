# 测试任务：铁路站点坐标与门到门候选排序

> 对应开发任务：`docs/Dev/task_from_arc_for_dev_20260814_rail_station_geodata.md`。

## 1. 目录完整性

- 校验全部铁路节点都有唯一 `station_code` 或明确的迁移/禁用原因。
- 校验所有 `planning_enabled` 客运站具有非空、合法、`VERIFIED` 坐标及独立来源元数据，覆盖率必须为100%。
- 校验 `AMBIGUOUS`、`NOT_FOUND`、`INVALID` 节点均为禁用，且不会进入候选。
- 校验 station code 唯一；上海虹桥等 seed/12306记录合并为一个活动实体。
- 校验坐标主数据不含 `service_date` 唯一维度；同一 station code 在多个服务日期、车次和停站记录中始终引用同一条坐标记录。
- 校验越界坐标、城市不一致、同 code 大幅漂移和来源缺失均阻止 staging 激活。

## 2. 导入可靠性

- 使用fixture覆盖 dry-run、checkpoint、resume、重复执行幂等、超时、限流和中断。
- 构造同一车站覆盖D0、D+1、D+14三个服务日的fixture，断言只调用一次坐标来源、只生成一条活动坐标记录；每日时刻表刷新不得触发重复地理编码。
- 已有 VERIFIED 坐标且来源版本未变化时必须命中复用；来源版本变化或显式强制复核时才允许更新同一 station code 记录。
- 失败导入不替换上一活动目录；成功导入原子激活。
- 同名多站或搜索返回城市中心时进入歧义/无效状态，不自动取第一条。
- 测试不得访问未批准来源，不记录Secret或第三方原始敏感响应。

## 3. 站点语义回归

- “上海南翔格林公馆”不得强匹配上海南站。
- “上海南站”必须精确命中上海南站。
- “南翔北站”必须按 station code `NEH` 命中唯一实体。
- 普通POI包含某站名称片段时不得形成精确站点匹配。
- 缺坐标或非 VERIFIED 站点不会以零距离或 `hub_rank` 进入候选。

## 4. 附近站点与双端接驳

- 固定格林公馆、南翔北、上海虹桥、上海南坐标和地图fixture，验证按真实接驳而非字符串或枢纽等级排序。
- 构造最近站无合适车次、次近站有合适车次的运行图，验证可达性参与选择。
- 出发端和到达端均执行相同候选流程；构造苏州、苏州北、苏州南末程接驳差异，验证超长末程方案不会未经比较胜出。
- 地图不可用时对应候选fail-closed并给出诊断，不生成默认距离、时间或费用。

## 5. 站点对全局比较

- 第一站点对返回10条可售车次，验证Planner仍按预算检查其他优先站点对。
- 多站点对核票完成后，验证 `max_plans` 只裁剪全局排序结果，不控制探索提前返回。
- 验证全局排序使用完整门到门时间、费用、换乘和风险，不只比较铁路段。
- 验证查询预算耗尽时结果和诊断一致，不出现无界站点组合或重复核票。

## 6. 集成与回归

- 南翔格林公馆到苏州用例至少覆盖：南翔北可达、南翔北不可达、上海虹桥更优、目的地站接驳差异四种fixture。
- 本地快照关闭或不可用时，现有回滚路径行为保持稳定，但不得恢复子串伪强匹配。
- 未经FlyAI实时验证的本地车次仍不形成可预订计划。
- 运行后端全量pytest、数据目录质量检查、Schema diff；外部API合同预期无变化。

## 完成门禁

- 活动规划站坐标覆盖率100%，重复station code为0，未知坐标进入候选数量为0。
- 同一站点跨任意服务日期的坐标活动记录数为1，正常增量刷新产生的重复坐标请求数为0。
- “上海南翔格林公馆 -> 上海南站”子串误匹配回归为0。
- 第一站点对填满展示数量导致的提前停止次数为0。
- 所有fixture和后端全量回归通过；真实坐标来源smoke未执行时必须明确记录为未验证。
